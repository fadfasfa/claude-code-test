# Hextech 伴生系统设计

当前源码：三进程与引用型 release v4。源码与隔离测试不代表正式安装已升级；真实 League 验收单列。

## 依赖方向

`src/hextech` 的 contracts 定义数据与身份，modules 持有业务及只读查询，interfaces/infrastructure 提供输入输出，bootstrap 组装具体实现。不存在第二套常驻协调器、通用插件框架或数据库服务。

## 进程与热路径

App 是唯一生命周期 owner：创建独立 Overlay 和 Vision，绑定 Windows Job，检查实例身份，负责异常恢复与有界退出。DataService 是 App 内的后台用例，不再是 HTTP 服务；Supervisor 职责收回 App，不再有独立端口或租约。

App 与各子进程用有界本地管道传递当前版本消息。Vision→App→Overlay 的转发运行在后台，不等待 Tk。消息绑定 Build、实例、游戏、epoch、序号和时间，过期、乱序或前局消息不能进入当前显示。状态只保留最新值，控制请求有明确结果或超时。Context 在 App 内存中维护，Overlay 使用新鲜 publication；生产不读取旧事件/Context JSON作回退。

桌面备战席与游戏 Overlay 继续分属两个 GUI 进程。原生窗口、no-activation、捕获排除、同屏外贴、混合 DPI、固定几何与独立显隐规则不变。Vision 原生OCR与截图故障不应直接带走任一GUI。网络、校验、投影、报告与截图证据保存均在后台。

## 官方身份与来源

生产身份来自腾讯官方 `https://game.gtimg.cn/images/lol/act/img/js/kiwi/kiwi_augments.json`，精确匹配 KIWI，排除 PBE；数量不写死，`isNew`不影响资格。官方名称与内部名进入规范目录。CDragon为资源补充，失败不否决官方身份；冲突图标不绑定，缺图按通道降级。静态名单不冒充实时热禁用信息。

统计来自 ARAMKit：排行与单英雄 all/Stage 1–4 是独立不可变单元。Apex/Mayhem 继续分别验证、提供联动，失败不清空有效核心数据。Blitz与旧Hextech/CSV链不再出现在生产worker、启动回退或冻结依赖中。

条件请求复用验证过的正文。相同版本且完整不重复下载/发布；网络退避及Retry-After不因后台调用而绕过。未知身份合并触发名单检查；目录身份改变后，仅相关绑定失败可重投影原文，不全局解除网络退避。

## 唯一发布真源与查询

`var/snapshots` 保存以 generation_id 标识的 schema 4 release manifest，包含Catalog、ranking、每英雄与optional联动的精确引用、来源版本、路径、大小和哈希。不可变来源单元只存一份，不再持久化第二份全英雄hints/API预计算详情。

发布由App中的唯一数据所有者执行。新引用闭包完全验证后原子更新head，current与previous不分步提交。失败保留完整上一代；未知、损坏、跨Catalog和缺失child拒绝。识别Catalog能独立推进，统计视图按本局首选截止冻结；新目录不等待全英雄统计。

只读View按需投影。排行读取不打开英雄详情；单英雄详情只读对应unit/index/child，LRU容量二；名称、身份和联动hints不复制全英雄百分比。返回的可变结果是独立副本，不能污染已发布数据。条件检查状态不写入业务内容指纹。

新版生产仅支持v4。离线转换器只接受完整有效v3闭包，写入不存在的独立目标目录；原目录保持只读，更旧格式不进入新版常驻读取分支。v4 seed与真实运行目录相互隔离。

## 诊断与验收

保留有界选卡时间线、在线终态摘要、会话报告、必要异常ROI与低频最新状态；退出重复trace history写入。摘要在时间线截断前累计，明确历史是否完整，不能把内部READY当作人眼呈现。

选择证据保留200组/256MiB及人工/未知/部分写入保护。相同内容和容量状态下，确定失败不重复PNG编码；容量拒绝记录所需/瞬时峰值/可轮转字节。不清理历史数据来掩盖留存问题。App调度全局留存，Vision只保存自己的有界证据并请求调度。

必须分别验证断网/304/损坏缓存、官方名单变化、进程崩溃、乱序与跨局消息、发布中断、重启恢复、原生窗口和真实游戏。30秒准备、180ms识别、900ms三槽呈现及100ms事件到呈现等既有性能目标不能以静态检查冒认通过。正式打包、真实目录转换、部署与清理不属于源码重构的自动动作。
