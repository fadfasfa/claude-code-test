# 验证与审查

本文件定义完成前的最小验证、本地审查和收尾报告规则。

## 最小验证

- 修改代码必须运行与风险及变更范围相称的最小有效验证；既有专项验收要求继续适用。
- 必要检查通过后，没有新改动、新失败或具体未解决疑点就结束验证，不无条件扩大或重复测试。
- 修改 PowerShell 脚本必须做 parse check。
- 修改文档至少检查 diff、路径引用和禁止路径是否被触碰。
- 文档或规则移动：运行 `rg` 检查旧路径残留，运行相关测试。
- Python 脚本改动：运行目标脚本测试或最小 pytest。
- Skill / workflow 改动：检查触发场景、禁止事项、验证说明和路径引用。
- 无法验证时说明具体原因，不宣称完成。

## 本地审查

- commit 或 PR 前读取 `git status --short`、`git diff --stat`、`git diff --name-status`。
- 检查是否触碰业务工作区、受保护路径、凭据名或未授权工作区。
- staged 清单必须只包含本轮授权范围。
- 审查输出优先列风险和缺失验证，再列摘要。
- 本地 review 不等于测试通过；必须单独报告实际验证命令和结果。

## 按需独立复核

- 本地自检和最小有效验证是默认完成条件，不强制子智能体审查。
- 只有用户或适用 Skill 明确要求代理协作时，才使用只读 reviewer，并服从宿主权限；疑点和风险应报告，不自动升级为审查门禁。
- reviewer 只报告问题和建议验证，不修改文件、不参与权限升级或 Git 授权扩散。

## 提交边界

- 默认不提交。
- 文件修改后，必须先完成最小有效验证并报告 diff、验证结果和剩余风险。
- 只有用户明确授权 commit，或满足 `docs/当前规则/20-Git与高危操作.md` 的已有开放 PR 修复例外时，才提交本轮修改；一般计划批准不替代该授权。
- commit 只允许包含本轮修改文件。
- 提交前必须用 `git status --short`、`git diff --name-status` 和 staged 清单确认无关脏树、历史 staged 内容、用户未授权修改没有进入本轮提交。
- 禁止 `git add .`。
- commit 完成后必须再次检查 `git status --short`。

## 收尾报告

修改任务按根 `AGENTS.md` 的语言约定交付，集中说明：

- 修改文件与实际涉及的登记工作区，既有脏改和受保护范围是否保持不变；无需逐个列出无关业务目录。
- 是否执行删除、清理、移动，以及 staging、commit、push 等实际 Git 动作。
- 验证命令、结果、剩余风险和未验证点；实际使用子智能体时才记录其结果。

`TASK_HANDOFF.md` 和 `.task-worktree.json` 只属于显式 worktree / finalize / local-review 流程；普通 Codex 修改任务不生成或更新这些文件。
