# 入口总览

本文件是当前 workflow 的最短入口规则。详细任务按 `docs/index.md` 路由到本目录其他文件。

## 默认流程

1. 先运行 `git status --short`；发现非本轮修改时先报告并避免混入。
2. Codex 入口读取 `AGENTS.md`、`PROJECT.md`、`docs/index.md`。
3. Claude Code 入口读取 `CLAUDE.md`、`PROJECT.md`、`docs/index.md`。
4. 写入前从 `docs/当前规则/10-工作区登记.md` 选择目标工作区。
5. 非琐碎治理、代码或配置任务先说明目标、非目标、关键假设和验证方式。
6. 长任务按合适阶段拆分；每阶段完成后必须通过子智能体审查，才进入下一阶段。
7. 修改后运行最小有效验证；无法验证时说明具体原因。
8. 验证通过后报告 diff、验证结果和剩余风险。
9. commit、push、PR、merge、rebase、tag、discard、删除或清理只在当前轮明确授权范围内执行。
10. 禁止 `git add .`；commit 前只能暂存本轮修改文件。

## 输出语言

- 默认使用简体中文输出计划、进展、问题、风险、验证结果、审查结论和最终总结。
- 生成计划文档、治理文档或任务总结时，正文必须使用简体中文，除非用户明确要求其他语言。
- 技术标识符、路径、命令、API 名称、错误原文、分支名和 Skill 名称保持原文。
- 生成英文计划视为未满足本仓维护规则，交付前必须改为中文。

## 子智能体阶段门禁

- 阶段实现后先做本地自检。
- 再派 spec-compliance 子智能体检查是否符合本阶段目标。
- spec PASS 后再派 maintainability / code-quality 子智能体检查可维护性、边界和遗漏。
- 任一审查失败时先修复并复审，不进入下一阶段。
- 子智能体 prompt 必须自包含，明确目标、范围、禁止事项、输出要求和 owned files / modules。
- 子智能体默认使用简体中文输出；路径、命令和错误原文保持原文。
- 长任务阶段包和 reviewer prompt 模板见 `docs/参考资料/策略说明/long-task-stage-gate.md`。

## 产物边界

- 普通任务只产出目标 diff 和对话摘要。
- `.state/workflow/**` 是旧 CC-CX 工作流遗留运行态目录；当前工作流不依赖旧任务结果文件。
- `.state/cc-work/**` 可用于本机计划、协作、交接和审查草稿；不是正式文档区。
- `.claude/plans/**` 只用于 Claude Code 原生本机计划草稿；默认不提交。
- 普通任务不默认生成 `docs/方案草稿/*.md`、Markdown report、probe 或 archive 证据文件。
- 工作区重新打包或重建可分享发布产物时，成功并通过最小验证后默认同时产出交付目录和对应压缩包，并替换同一打包目标下的旧压缩包、旧交付目录和旧中间产物；失败时不提前删除旧可用产物，且不得使用 `git clean` 或泛化清理命令清理无关 `dist/cache/log/runtime`。
