# 入口总览

本文件是当前 workflow 的最短入口规则。详细任务按 `docs/index.md` 路由到本目录其他文件。

## 默认流程

1. 先运行 `git status --short`；发现非本轮修改时先报告并避免混入。
2. Codex 遵循 `AGENTS.md`；项目定位不清时读 `PROJECT.md`，专项规则从 `docs/index.md` 按任务选读，已加载且未变化的规则不重复通读。
3. Claude Code 从 `CLAUDE.md` 进入，项目定位和专项规则按任务选读。
4. 写入前从 `docs/当前规则/10-工作区登记.md` 选择目标工作区。
5. 非琐碎治理、代码或配置任务先说明目标、非目标、关键假设和验证方式。
6. 长任务按需要拆分阶段并逐段自检；不因任务规模自动派子智能体或设置 reviewer 门禁。
7. 修改后运行最小有效验证；无法验证时说明具体原因。
8. 验证通过后报告 diff、验证结果和剩余风险。
9. Git、删除和清理遵循 `docs/当前规则/20-Git与高危操作.md`；Codex 的普通 Git 一次授权语义以用户级 `AGENTS.md` 为准，本文件不重复维护，已有开放 PR 修复按专项文档的例外执行。

## 输出语言

交流语言遵循各自用户级约定；本仓文档和 Git 交付语言按 `PROJECT.md` 及专项规则执行。

## 子智能体边界

- Codex 按用户级 `AGENTS.md` 按需委派可独立交付的任务；Claude Code 遵循自己的用户级规则。委派服从宿主权限，不作为固定流程或验收门禁，Claude Code 不隐式调用 Codex / CX。
- Plan Mode 不派写入型子智能体；子智能体不参与权限升级或 Git 授权扩散。
- 子智能体 prompt 必须自包含，明确目标、范围、禁止事项和输出要求。

## 产物边界

- 普通任务只产出目标 diff 和对话摘要。
- `.state/workflow/**` 是旧 CC-CX 工作流遗留运行态目录；当前工作流不依赖旧任务结果文件。
- `.state/cc-work/**` 可用于本机计划、协作、交接和审查草稿；不是正式文档区。
- `.claude/plans/**` 只用于 Claude Code 原生本机计划草稿；默认不提交。
- 普通任务不默认生成 `docs/方案草稿/*.md`、Markdown report、probe 或 archive 证据文件。
- 工作区重新打包或重建可分享发布产物时，成功并通过最小验证后默认同时产出交付目录和对应压缩包，并替换同一打包目标下的旧压缩包、旧交付目录和旧中间产物；失败时不提前删除旧可用产物，且不得使用 `git clean` 或泛化清理命令清理无关 `dist/cache/log/runtime`。
