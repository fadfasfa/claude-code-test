# 退役边界

本文件记录旧流程、旧入口和禁止恢复边界。

## Codex / Claude Code 边界

- Claude Code 与 Codex 均可独立完成普通仓库任务。
- Codex App、VS Code Codex、Codex CLI、wrapper 和 Claude Code 调用器是不同 surface，不混写为同一入口。
- Claude Code 没有用户当前轮显性点名或命令时，不得调用、委派、审查或触发 Codex / CX。
- `.claude/settings.json` 可保留 Codex plugin 启用状态；启用状态不构成 Claude Code 调用 Codex 的默认偏好或隐含授权。
- Codex plugin review gate 默认禁用，除非用户显性要求。

## 旧 CC-CX 退役状态

- 旧 CC-CX 根入口和旧 workflow executor 已移除。
- 不再维护旧 CC-CX 执行脚本作为主流程、fallback 主路或验收接口。
- `.state/workflow/**` 是旧 CC-CX 工作流遗留运行态目录；当前工作流不依赖旧任务结果文件。
- `docs/历史归档/cc-worker/` 只作为历史和恢复材料，不是 active workflow。
- 旧 CC-CX 强编排、Guard 状态机和 break-glass 流程已经退役，不作为日常入口。

## Codex 出口边界

- Codex 出口维护是独立高风险维护任务，不属于普通仓库实现任务或默认执行边界。
- 涉及 `Codex Proxy`、`cockpit-cliproxy`、Clash、mihomo、`7898`、`7899`、Codex 出口或账号池隔离时，本文件只给出边界；本地维护细节如需记录，应放在被忽略的 `docs/参考资料/本地维护/codex-egress-maintenance.md`，不得作为第八个 active 规则源。
- 本仓当前规则不保存 live proxy 细节、节点名、订阅 URL、账号、密钥或路由真相。
- 不读取或修改 `auth.json`、token、cookie、API key、`local.yaml`、`proxies.json` 或 proxy secret。

## Ultraplan

- Ultraplan 只保留后续接入备注。
- 没有用户明确要求时，不新增 Ultraplan workflow、hook 或长期状态。
- 后续确认 Claude Code on the web 与 `/ultraplan` 可用后，再单独评估入口命令、计划产物落点、验证规则和发布边界。
- 小任务仍由 Claude Code 或 Codex 独立完成，不需要经过 Ultraplan。
