# 工作区登记

本文件是仓库工作区和默认写入边界事实源。仓库根目录默认只做治理，不承载业务实现。

## 默认规则

- 默认可读范围：整个仓库，排除敏感文件和用户明确禁止路径。
- 默认可写范围：选定目标工作区的目录树。
- 新工作区先走 `repo-module-admission`，再登记到本文件。
- Git worktree 是执行面，不自动成为活动工作区。
- 目标不清时保持只读，列出候选工作区。
- 任何备份失败都必须立即停止。

## 写入选择

1. 实现前声明 `target_work_area`。
2. `allowed_write_scope` 默认等于目标工作区写入范围。
3. 目标不清时保持只读，列出候选工作区。
4. 任何跨工作区重构、批量格式化、迁移生成物或删除运行态目录都属于高风险动作。

## 本轮治理重构保护

治理重构和文档整理不得触碰业务工作区。若任务明确要求与其他工作树并行，必须同时检查 tracked、untracked、unstaged 和 staged 状态：

```powershell
git status --short -- run sm2-randomizer sms-monitor heybox subtitle_extractor QuantProject qm-run-demo
git diff --name-only -- run sm2-randomizer sms-monitor heybox subtitle_extractor QuantProject qm-run-demo
git diff --cached --name-only -- run sm2-randomizer sms-monitor heybox subtitle_extractor QuantProject qm-run-demo
```

以上任一命令有输出时，必须先停止并排除业务工作区改动。
